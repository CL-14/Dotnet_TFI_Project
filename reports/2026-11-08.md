# Weekly Project Report — 8 November 2026

## Project title and description

**Where Is that ghost bus? / still same name, for now**

It's a reliability-focused Dublin bus tracking web application. The project builds a C# web application (ASP.NET Core Razor pages, SQLite) on the NTA's open GTFS and GTFS-Realtime data. It will show live bus positions and service alerts and can also estimate service reliability by comparing scheduled trips with the vehicles actually observed.

## User Stories Completed This Week

- US19 (continuous data collector), in progress: the SQLite database for the collector, with tables for trip history, trip predictions, a poll log, the latest vehicle positions and the current alerts, plus automated tests. The last two tables are groundwork for US1, US3 and US7 (live map, nearby buses, alerts): only the collector will call the NTA API, and the web application will read from the database.
- The feed client now fetches all three NTA feeds (vehicles, trip updates, alerts), checked against the live API. I found a bug that made every request return 404 was found and fixed it.
- Feed mappers that convert each feed into plain records (vehicle positions, trip predictions with their delay, and alerts), with unit tests built from hand made feeds.

## What went well

- Each new piece has automated tests, and I check them by breaking the code on purpose to see them fail.
- The decision that only the collector calls the NTA API keeps the project inside the usage policy since NTA has not responded to my email.
- Trip IDs are shared across all three feeds, which keeps the reliability analysis workable.

## What didn't go well / issues encountered

- The compiler warned that the alerts' active_period field is deprecated in the current GTFS-Realtime specification (and I need to find what is the updated field name). I need to check which fields the NTA actually fills in and handle both.
- I have not yet received feedback on the proposal, and I have not had a reply from NTA API support on the usage limits.
